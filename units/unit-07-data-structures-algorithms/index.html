1. Data Structures

Data structures organize data so it can be stored, accessed, and updated efficiently — the choice of structure often decides an algorithm's performance.

In simple words: A data structure is just a specific way of arranging data so certain operations become fast. A stack is like a pile of plates (you only add/remove from the top); a queue is like a line at a shop (first person in line is served first); trees let you find things quickly by repeatedly narrowing down which half to look in.

Key ideas

  • Arrays & sparse matrices: arrays give O(1) indexed access; a sparse matrix (mostly zeros) is stored compactly (e.g. as a list of non-zero (row, col, value) triples) instead of a full 2D array.
  • Stacks, queues, priority queues: a stack is LIFO (last-in-first-out); a queue is FIFO (first-in-first-out); a priority queue always removes the highest (or lowest) priority element next, commonly implemented with a heap.
  • Linked lists: nodes connected by pointers allow O(1) insertion/deletion (given a reference) without shifting elements, unlike arrays.
  • Trees, forests, binary trees: a tree is a hierarchical, acyclic structure; a forest is a set of disjoint trees; a binary tree limits each node to at most two children.
  • Threaded binary trees replace some null child pointers with "threads" to the in-order predecessor/successor, enabling traversal without a stack or recursion.
  • Binary Search Tree (BST): keeps left-subtree keys smaller and right-subtree keys larger than the node's key, enabling O(h) search/insert/delete (h = tree height).
  • AVL trees: self-balancing BSTs that keep every node's left/right subtree heights within 1 of each other via rotations, guaranteeing O(log n) operations.
  • B-Tree, B+ Tree, B* Tree: balanced multi-way search trees (each node holds many keys/children) designed to minimize disk reads for large, disk-resident indexes (databases, file systems); B+ Trees additionally chain all leaf nodes together for fast sequential/range scans.
  • Data structures for sets, graphs: bit-vectors or union-find (disjoint-set) structures represent sets efficiently; graphs are stored via adjacency matrices or adjacency lists.
  • Sorting, searching & hashing: sorting algorithms (covered further under design techniques) order data; searching locates elements (linear vs. binary search); hashing maps keys to array indices for expected O(1) lookup, resolving collisions via chaining or open addressing.

2. Performance Analysis of Algorithms and Recurrences

Before comparing algorithms, we need a precise, hardware-independent way to describe how their running time and memory use grow with input size.

In simple words: Instead of timing an algorithm in actual seconds (which depends on the computer it runs on), Big-O describes how the work grows as the input gets bigger — "doubling the input roughly doubles the time" (O(n)) versus "doubling the input roughly quadruples the time" (O(n²)). That's what lets us compare algorithms fairly.

Key ideas

  • Time & space complexity: time complexity measures operations as a function of input size n; space complexity measures memory used.
  • Asymptotic notation: O (big-O) gives an upper bound on growth; Ω gives a lower bound; Θ gives a tight bound (both upper and lower) — used to describe worst-, best-, and average-case behavior.
  • Recurrence relations: express a recursive algorithm's running time in terms of itself on smaller inputs (e.g. T(n) = 2T(n/2) + n for merge sort); solved via substitution, recursion trees, or the Master Theorem.

3. Design Techniques

A handful of general strategies recur across many efficient algorithms, each suited to different problem structures.

In simple words: These are general strategies for attacking a problem: split it into smaller copies of itself (divide and conquer); remember answers to sub-problems you've already solved so you never redo work (dynamic programming); just grab whatever looks best right now (greedy); or try a choice and undo it the moment it clearly won't work (backtracking).

Key ideas

  • Divide and conquer: break a problem into independent subproblems, solve each recursively, then combine their solutions (e.g. merge sort, quicksort, binary search).
  • Dynamic programming: applies when a problem has overlapping subproblems and optimal substructure — solves each distinct subproblem once and reuses (memoizes) the result (e.g. shortest paths, knapsack, edit distance).
  • Greedy algorithms: make the locally best choice at each step; correct only when the problem has the "greedy-choice property" (e.g. Kruskal's/Prim's MST, Huffman coding) — not always globally optimal in general.
  • Backtracking: incrementally builds candidate solutions, abandoning ("pruning") a partial solution as soon as it can't possibly lead to a valid one (e.g. N-Queens, Sudoku).
  • Branch and bound: systematically searches for an optimization problem's best solution, using bounds to prune branches that provably can't beat the best solution found so far.

4. Lower Bound Theory

Beyond finding fast algorithms, lower bound theory proves how fast a problem could ever be solved — establishing when an algorithm is already optimal.

In simple words: Sometimes we can prove not just "here's a fast algorithm" but "no algorithm could ever be faster than this" — that's a lower bound. For example, no comparison-based sorting method can ever beat roughly n·log(n) comparisons in the worst case, no matter how cleverly it's written.

Key ideas

  • Comparison trees (decision trees): model any comparison-based algorithm as a binary tree of comparisons; the tree's minimum possible height gives a lower bound on worst-case comparisons — this is how Ω(n log n) is proven for comparison-based sorting.
  • Lower bounds through reductions: if a problem with a known lower bound can be reduced (transformed) to a new problem using only "cheap" extra work, that lower bound carries over to the new problem too.

5. Graph Algorithms

Many real-world problems — networks, dependencies, routes — are modeled as graphs, and a core set of algorithms solves the most common questions about them.

In simple words: A graph is just dots (vertices) connected by lines (edges) — like cities connected by roads. BFS and DFS are two different ways to visit every dot; Dijkstra's finds the cheapest route between two points; a Minimum Spanning Tree finds the cheapest way to connect every dot together without any wasteful extra connections.

Key ideas

  • Breadth-First Search (BFS): explores a graph level by level using a queue — finds shortest paths by edge-count in unweighted graphs.
  • Depth-First Search (DFS): explores as far as possible along each branch before backtracking, using a stack (explicit or via recursion) — used for cycle detection, topological sort, connected components.
  • Shortest paths: Dijkstra's algorithm finds single-source shortest paths with non-negative weights; Bellman-Ford handles negative weights (and detects negative cycles); Floyd-Warshall finds all-pairs shortest paths.
  • Maximum flow: algorithms like Ford-Fulkerson find the greatest flow deliverable from a source to a sink through a capacitated network.
  • Minimum Spanning Trees (MST): Kruskal's and Prim's algorithms find a tree connecting all vertices with minimum total edge weight.

6. Complexity Theory

Complexity theory classifies problems by the resources needed to solve them, revealing which problems are fundamentally "hard."

In simple words: P is "problems we can solve quickly." NP is the bigger set of "problems where, if someone hands you an answer, you can at least check it quickly" (even if finding that answer yourself might be very slow). NP-complete problems are the hardest problems in NP — solve any one of them fast, and you've effectively solved them all.

Key ideas

  • Class P: problems solvable by a deterministic algorithm in polynomial time.
  • Class NP: problems whose proposed solutions can be verified in polynomial time (not necessarily solved that fast).
  • NP-completeness: a problem is NP-complete if it's in NP and every other NP problem can be reduced to it in polynomial time — so an efficient algorithm for one NP-complete problem would efficiently solve all of NP.
  • Reducibility: transforming one problem into another in polynomial time is the key tool for proving NP-completeness and comparing problem difficulty.
  • Whether P = NP is one of the most famous unsolved problems in computer science/mathematics.

7. Selected Topics

A grab-bag of specialized but widely used algorithms for numeric, symbolic, and text-processing problems.

In simple words: These are specialized workhorse algorithms: number-theoretic tricks (like fast GCD and primality testing) power much of modern cryptography, the FFT speeds up signal/frequency analysis, and pattern-matching algorithms like KMP find a word inside a big block of text far faster than checking every possible starting position one by one.

Key ideas

  • Number theoretic algorithms: efficient GCD (Euclidean algorithm), modular exponentiation, and primality testing underlie much of cryptography.
  • Polynomial arithmetic: efficient multiplication/evaluation of polynomials, foundational for many numeric algorithms.
  • Fast Fourier Transform (FFT): computes the Discrete Fourier Transform in O(n log n) instead of the naive O(n²), and is also used to multiply large polynomials/integers quickly.
  • String matching algorithms: KMP and Boyer-Moore find a pattern within a text faster than naive comparison by reusing information from earlier partial matches.

8. Advanced Algorithms

When exact, deterministic, single-processor algorithms aren't fast or practical enough, these approaches trade off in different directions.

In simple words: Sometimes the "textbook" single-processor, exact, deterministic algorithm just isn't good enough — so we split the work across many processors at once (parallel), settle for a solution that's provably close enough rather than perfect (approximation), or let the algorithm make random choices to sidestep worst-case scenarios (randomized).

Key ideas

  • Parallel algorithms: sorting, searching, and merging can be sped up by dividing work across multiple processors running simultaneously.
  • Approximation algorithms: for NP-hard optimization problems, these efficiently find a solution provably close to optimal, when an exact solution isn't feasible in polynomial time.
  • Randomized algorithms: make random choices during execution (e.g. randomized quicksort's pivot choice) to achieve good expected-case performance or simplicity, even when worst-case behavior is hard to avoid deterministically.
