1. Digital Logic Circuits and Components

Every digital computer is built from circuits that manipulate 0s and 1s. Logic gates (AND, OR, NOT, NAND, NOR, XOR) are the basic building blocks; Boolean algebra and map simplification (K-maps) minimize the gates needed to implement a function.

Key ideas

  • Combinational circuits: output depends only on current inputs (adders, decoders, multiplexers, encoders) — no memory.
  • Sequential circuits: output depends on current inputs and past state, stored in flip-flops (SR, D, JK, T) — the building blocks of registers and counters.
  • Decoders activate exactly one output line based on an n-bit input code; multiplexers do the reverse — select one of many inputs onto a single output line.
  • Registers store multi-bit data (built from flip-flops); counters are registers that step through a sequence of states.
  • Integrated circuits (ICs) package these gates at increasing densities (SSI → VLSI); the memory unit stores instructions and data as arrays of bits.

2. Data Representation

Computers represent all data — numbers, text, instructions — as binary patterns. This topic covers how numbers are encoded and how arithmetic is performed on those encodings.

Key ideas

  • Number systems: binary, octal, decimal, hexadecimal, and conversion between them.
  • Complements: 1's complement (bit-flip) and 2's complement (bit-flip + 1) let subtraction be done as addition; 2's complement is used in nearly all modern hardware since it has a single representation of zero.
  • Fixed-point representation assumes an implicit binary point at a fixed position; floating-point (IEEE 754) trades some precision for a huge dynamic range using sign, exponent, and mantissa fields.
  • Error detection codes: parity bits (detect single-bit errors), checksums, Hamming code (can also correct single-bit errors).
  • Computer arithmetic: addition/subtraction via 2's complement adders; multiplication (Booth's algorithm) and division algorithms operate through repeated shift-and-add/subtract steps.

3. Register Transfer and Microoperations

Register Transfer Language (RTL) is a symbolic notation (e.g. R2 ← R1) used to precisely describe the microoperations that move and transform data between registers inside a CPU.

Key ideas

  • Bus and memory transfers: a common bus reduces wiring by multiplexing many register outputs onto shared lines; memory transfers use RTL like M[AR] ← R or R ← M[AR].
  • Arithmetic microoperations: add, subtract, increment, decrement performed a register-transfer step at a time.
  • Logic microoperations: bitwise AND, OR, XOR, complement between registers.
  • Shift microoperations: logical shift (fills with 0), arithmetic shift (preserves sign bit), and circular shift (rotate) — used for multiplication/division and bit manipulation.

4. Basic Computer Organization and Design

A simple hypothetical computer illustrates how instructions actually get fetched from memory and carried out — the model behind every real CPU.

Key ideas

  • Stored program concept: instructions and data share the same memory, so instructions can be fetched and treated as data (e.g. self-modifying code, loaders).
  • Computer registers: PC (Program Counter), AR (Address Register), IR (Instruction Register), AC (Accumulator), DR (Data Register) each play a defined role.
  • Instruction format: an opcode plus an address, with an indirect-addressing (I) bit deciding whether the address field points directly to the operand or to a pointer to it.
  • Timing and control: a sequence counter (SC) and decoder generate timing signals that drive each micro-step of the cycle.
  • Memory-reference instructions (e.g. AND, ADD, LDA, STA) operate on a memory operand; I/O and interrupt instructions handle communication with peripherals and asynchronous events.

5. Programming the Basic Computer

Once the hardware can execute an instruction cycle, programs are written to drive it — starting from raw machine code up through structured assembly programming.

Key ideas

  • Machine language: raw binary opcodes/operands the CPU executes directly.
  • Assembly language: human-readable mnemonics (e.g. LDA, ADD, STA) mapped one-to-one (mostly) to machine instructions.
  • Assembler: a two-pass program that translates assembly source into machine code, resolving labels/addresses on the second pass.
  • Program loops: a counter (index register) is decremented/incremented and tested each iteration to control repetition.
  • Subroutines: reusable, callable code blocks that save the return address and restore control via a return instruction — enabling modular programs.
  • Input-Output programming: programs poll status flags or respond to interrupts to synchronize data transfer with slower peripheral devices.

6. Microprogrammed Control

Instead of hardwired logic, a control unit can be built from a small stored "program" of control words — trading raw speed for flexibility and easier design changes.

Key ideas

  • Control memory: a (typically ROM) memory holding microinstructions — each word's bits directly drive control signals for one micro-step.
  • Address sequencing: logic that determines the next microinstruction's address — sequential execution, conditional branching, or a mapping from the instruction's opcode.
  • Design of the control unit: a microprogram counter steps through control memory, generating the exact sequence of signals needed to execute each machine instruction.
  • Trade-off: microprogrammed control is more flexible and easier to modify/debug than hardwired control, at the cost of extra memory-access latency per micro-step.

7. Central Processing Unit

The CPU organizes registers, defines how instructions are formatted, and decides how operand addresses are computed — choices that separate classic RISC and CISC design philosophies.

Key ideas

  • General register organization: multiple general-purpose registers reduce memory traffic compared to a single-accumulator design.
  • Stack organization: a LIFO structure (register or memory based) enables efficient zero-address instructions, natural for expression evaluation (postfix/RPN).
  • Instruction formats: zero-, one-, two-, and three-address formats trade instruction length for the number of explicit operands.
  • Addressing modes: immediate, direct, indirect, register, register-indirect, indexed, relative — each computes the effective operand address differently.
  • RISC: small, fixed-length, simple instruction set; many registers; heavy use of pipelining; load/store architecture.
  • CISC: larger, variable-length instruction set with complex, multi-cycle instructions and many addressing modes.

8. Pipeline and Vector Processing

Rather than finishing one instruction fully before starting the next, a pipeline overlaps the stages of successive instructions — like an assembly line — to increase throughput.

Key ideas

  • Parallel processing: doing more than one operation at a time, at the circuit, instruction, or processor level.
  • Pipelining: splits instruction execution into stages (e.g. Fetch, Decode, Execute, Writeback) so multiple instructions overlap in flight.
  • Arithmetic pipeline: breaks a complex arithmetic operation (e.g. floating-point add) into pipelined sub-stages.
  • Instruction pipeline: pipelines the fetch/decode/execute stages of successive instructions — its throughput is hurt by data, control, and structural hazards.
  • Vector processing / array processors: apply a single instruction across an entire array of data elements simultaneously (SIMD), ideal for scientific/numeric workloads.

9. Input-Output Organization

Peripherals are far slower and less predictable than the CPU, so I/O organization is about bridging that gap efficiently.

Key ideas

  • Peripheral devices (keyboard, disk, printer, etc.) connect through an I/O interface that handles signal conversion, buffering, and timing.
  • Asynchronous data transfer: since CPU and device don't share a clock, a handshaking protocol (strobe, or request/acknowledge) synchronizes each transfer.
  • Modes of transfer: programmed I/O (CPU polls status), interrupt-driven I/O (device signals the CPU when ready), and DMA (bulk transfer bypassing the CPU).
  • Priority interrupt: when multiple devices request service simultaneously, a priority scheme (software polling or hardware daisy-chain/parallel priority) decides service order.
  • DMA (Direct Memory Access): a dedicated controller transfers blocks of data directly between device and memory, freeing the CPU for other work.
  • Serial communication: transmits data one bit at a time over a single line — simpler wiring, used for long-distance or low-pin-count links (e.g. UART).

10. Memory Hierarchy

No single memory technology is simultaneously fast, large, and cheap — so systems layer several kinds together, trading off speed, size, and cost.

Key ideas

  • Main memory (RAM) holds actively running programs and data; auxiliary memory (disks, SSDs) provides large, non-volatile, long-term storage.
  • Cache memory sits between CPU and main memory, holding recently/frequently used data to exploit temporal and spatial locality and cut average access time.
  • Associative memory (content-addressable memory) is searched by content/value rather than by address — useful for cache tag lookups and lookup tables.
  • Virtual memory lets programs use an address space larger than physical RAM, via paging/segmentation with hardware-assisted address translation.
  • Memory management hardware (e.g. an MMU with a TLB) translates virtual to physical addresses and enforces protection between processes.

11. Multiprocessors

A multiprocessor system uses more than one CPU working together to increase throughput and reliability — raising new questions about how those CPUs share memory and stay coordinated.

Key ideas

  • Characteristics of multiprocessors: multiple CPUs share memory and I/O resources, communicating to cooperate on tasks.
  • Interconnection structures: common bus, crossbar switch, multiport memory, and hypercube/mesh networks trade off cost, scalability, and contention.
  • Interprocessor arbitration: resolves conflicts when multiple processors want the bus/memory at the same time.
  • Interprocessor communication and synchronization: mechanisms like shared flags, semaphores, and message passing coordinate cooperating processors.
  • Cache coherence: keeps multiple processors' cached copies of the same memory location consistent after any one of them writes to it (e.g. via snooping or directory protocols).
  • Multicore processors: package multiple independent cores on a single chip, sharing some cache levels, to gain parallelism without the cost of separate chips.
