1. Language Design and Translation Issues

Before writing programs in any language, it helps to understand how that language is designed and how source code gets turned into something a machine can run.

Key ideas

  • Programming language concepts, paradigms & models: imperative, functional, logic, and object-oriented paradigms each offer a different mental model of computation.
  • Programming environments: the surrounding tools — editors, compilers/interpreters, debuggers, IDEs — that support writing and running programs.
  • Virtual computers & binding times: a language is really defined for an abstract "virtual machine"; binding time is when a property (type, storage, value) becomes fixed — at language-design, compile, link, or run time.
  • Programming language syntax: the grammar rules (often specified in BNF/EBNF) defining which token sequences form valid programs.
  • Stages in translation: lexical analysis (tokenizing) → syntax analysis/parsing → semantic analysis → intermediate code → optimization → target code generation.
  • Formal transition models: finite automata and transition diagrams formally specify how tokens/statements are recognized.

2. Elementary Data Types

Every language commits to a model of what a "type" is and which built-in types programs can use directly.

Key ideas

  • Properties of types and objects: a type defines a set of values plus the operations valid on them; an object is a run-time instance with its own storage, lifetime, and scope.
  • Scalar data types: single, indivisible values — integer, real/float, boolean, character, and enumeration types.
  • Composite data types: built from other types — arrays (same-type elements), records/structures (mixed-type fields), unions, and pointers.

3. Programming in C

C is a structured, procedural language whose direct control over memory (via pointers) makes it foundational for systems programming.

Key ideas

  • Tokens & identifiers: keywords, identifiers, constants, operators, and punctuators are the smallest meaningful units of a C program.
  • Data types: basic (int, float, char, double), derived (array, pointer, function), and user-defined (struct, union, enum).
  • Sequence & subprogram control: statements run sequentially unless redirected by selection (if/switch), iteration (for/while), or a function call/return.
  • Arrays, structures, unions: arrays hold same-type elements contiguously; structures group different-type fields; unions let alternative fields share the same memory.
  • Strings: represented as a char array terminated by a null character '\0'.
  • Pointers: variables holding a memory address — enabling indirection, dynamic memory allocation, and efficient array/parameter passing.
  • File handling: fopen/fread/fwrite/fclose read and write persistent data through file streams.
  • Command line arguments: argc/argv parameters to main() let a program receive input at invocation.
  • Preprocessor: directives like #include, #define, #ifdef are processed (macro substitution, conditional compilation) before the compiler proper runs.

4. Object Oriented Programming

OOP models software as a collection of interacting objects, each bundling its own data with the behavior that acts on it.

Key ideas

  • Class & Object: a class is a blueprint/type; an object is an instantiated instance holding its own state.
  • Instantiation: creating an object from a class — allocating storage and running a constructor.
  • Encapsulation: bundling data with the methods that operate on it, exposing only a controlled public interface.
  • Inheritance: a derived class reuses and extends a base class, modeling an "is-a" relationship.
  • Abstract class: cannot be instantiated directly — defines a common interface (possibly with pure/abstract methods) for its subclasses.
  • Polymorphism: the same call behaves differently depending on the actual object type — resolved at compile time (overloading) or run time (overriding via virtual functions).

5. Programming in C++

C++ extends C with object-oriented and generic-programming facilities, while keeping low-level control over memory and performance.

Key ideas

  • Tokens, variables, operators, control statements: largely as in C, plus references and a built-in bool type with stricter type checking.
  • Function parameter passing: by value, by pointer, or by reference; supports default arguments and function overloading.
  • Virtual functions: enable run-time polymorphism — the call is resolved based on the object's actual type, not the static type of the pointer/reference.
  • Constructors & destructors: automatically initialize an object at creation and clean it up at destruction (the basis of RAII resource management).
  • Overloading & inheritance: overloading gives the same name different parameter signatures (resolved at compile time); inheritance (single, multiple, multilevel, hierarchical) relates classes to each other.
  • Templates: generic functions/classes parameterized over a type, instantiated by the compiler for whichever type is used.
  • Exception & event handling: try/catch/throw let a program detect and recover from runtime errors instead of crashing.
  • Streams & files, multifile programs: cin/cout/fstream give type-safe I/O; large programs split declarations (headers) from definitions (source files) compiled and linked separately.

6. Web Programming

Web programming covers the technologies that structure, style, and dynamically generate content delivered between a browser and a server.

Key ideas

  • HTML / DHTML: HTML structures page content; DHTML combines HTML, CSS, and client-side scripting for dynamic, interactive pages.
  • XML: a markup language for structuring and exchanging self-describing data — for data, not presentation.
  • Scripting: client-side scripts (e.g. JavaScript) run in the browser, adding interactivity without a server round-trip.
  • Java, Servlets, Applets: servlets run on the server to generate dynamic content per request; applets were small Java programs run inside the browser (now largely obsolete).

7. Computer Graphics

Computer graphics is about how images are represented in memory and rendered as pixels on a display.

Key ideas

  • Video-display devices: CRT and modern flat-panel displays render an image as a grid of pixels.
  • Raster-scan vs. random-scan: raster-scan redraws the screen row by row from a frame buffer (used almost universally); random-scan (vector) draws only the outline strokes of a picture.
  • Line drawing algorithms: DDA and Bresenham's algorithm use only integer arithmetic to pick the pixels that best approximate a straight line.
  • Midpoint circle/ellipse algorithms: use the midpoint between two candidate pixels to decide the next pixel, exploiting symmetry (e.g. eight-way symmetry of a circle) to minimize computation.
  • Scan-line polygon fill: on each horizontal scan line, finds intersections with the polygon's edges and fills the pixels between paired intersections.
  • Boundary-fill & flood-fill: seed-fill algorithms that spread color from an interior point until hitting a boundary color (boundary-fill) or leaving the original color region (flood-fill).

8. 2-D Geometrical Transforms and Viewing

This topic covers the matrix math used to move, resize, and reorient 2D shapes, and how a scene is mapped onto the screen.

Key ideas

  • Basic transformations: translation (shift), scaling (resize), rotation (about a point), reflection (mirror), and shear (skew).
  • Homogeneous coordinates: represent 2D points as 3-vectors so translation, scaling, and rotation can all be expressed — and composed — as matrix multiplication.
  • Composite transformations: chaining several transformations (e.g. rotating about an arbitrary point = translate → rotate → translate back) by multiplying their matrices.
  • Viewing pipeline: world coordinates → viewing coordinates → normalized device coordinates → window-to-viewport mapping → device coordinates.
  • Window-to-viewport transformation: maps a rectangular window in world coordinates onto a viewport on the display device.
  • Clipping algorithms: Cohen–Sutherland and Liang–Barsky clip lines against a rectangular window; Sutherland–Hodgman clips polygons — discarding/trimming geometry outside the view.

9. 3-D Object Representation, Geometric Transformations and Viewing

3D graphics extends these ideas with richer surface representations, realistic shading, and projection onto a 2D screen.

Key ideas

  • Polygon surfaces: most 3D objects are approximated by a mesh of flat polygons (typically triangles) — the standard representation in real-time graphics.
  • Quadric surfaces: spheres, ellipsoids, cylinders, and cones defined compactly by second-degree equations.
  • Spline, Bezier & B-spline curves/surfaces: smooth curves/surfaces defined by a small set of control points — Bezier curves are shaped by all control points globally; B-splines give local control (only nearby points affect a segment).
  • Illumination models: compute ambient, diffuse, and specular light contributions (e.g. the Phong model) to shade a surface realistically.
  • Polygon rendering methods: constant (flat) shading, Gouraud shading (interpolates vertex intensities across a face), and Phong shading (interpolates surface normals) — increasing realism and cost in that order.
  • Viewing pipeline & projection transforms: modeling → world → viewing → projection → device coordinates; parallel/orthographic projection preserves relative size, while perspective projection mimics real vision (distant objects appear smaller).
  • Clipping: 3D clipping trims geometry against a view volume (frustum), extending 2D window clipping into three dimensions.
